# yDaemon RPC keys exposure

- **Date:** 2026-11-09
- **Reporter:** Akmal Ramadhasyifa (X: [@0xjoppy](https://x.com/0xjoppy)),
  via security@yearn.finance
- **Component:** yDaemon, legacy API kept running for integrators; outside the bug bounty scope
- **Status:** Fixed. Exposed RPC keys rotated.

## Problem

The unauthenticated endpoint `GET https://ydaemon.yearn.fi/info/chains` returned the full internal
chain configuration, including RPC and subgraph URLs with third-party API keys embedded in the path:

- Tenderly gateway RPC keys: Ethereum, Optimism, Polygon, Sonic, Arbitrum, Katana, Base
- Chainstack RPC keys: Gnosis, Fantom
- One shared The Graph gateway key: chains 1, 10, 42161

Anyone could collect these keys and use them to run down Yearn's provider quotas, add cost, or get
free RPC and subgraph access on Yearn's accounts. No user funds or smart contracts were affected.

## Fix

Commit [`8d812c5`](https://github.com/yearn/ydaemon/commit/8d812c563aedba383c35443ea2d0c7f6952c1eda)
(#571):

- Removed the `/info/chains` route and its handler (`external/utils/chains.go`)
- Removed the endpoint from the README
- Added a regression test that requires a 404 on `/info/chains` and that the response contains no
  `RpcURI`, `SubgraphURI`, or `EtherscanURI`

Verified on 2026-11-09: the live endpoint returns HTTP 404.

The exposed RPC keys have been rotated, so yDaemon no longer uses the leaked RPC secrets.
